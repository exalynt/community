# Exalynt Community

Welcome to the Exalynt community.

Exalynt is about **inspiring and supporting excellence in software engineering**. We build open-source tools, libraries, examples, and resources intended to help software engineers create systems that are simpler, more reliable, more maintainable, and easier to operate.

This repository is the community hub for the Exalynt GitHub organization.

## Get Involved

There are several ways to participate in Exalynt:

- 💬 Join conversations in [GitHub Discussions](../../discussions)
- 💡 Share ideas for projects, libraries, and improvements
- 🐛 Report bugs in the repository where the issue occurs
- 🛠️ Contribute code, documentation, tests, or examples
- 📖 Improve documentation and developer experience
- 🤝 Help other members of the community

You don't need to contribute code to contribute to Exalynt. Questions, feedback, ideas, documentation improvements, and real-world experience are all valuable.

## Contributing

Exalynt projects are developed openly and contributions are welcome.

Before contributing, please read our [Contributing Guide](CONTRIBUTING.md).

Individual repositories may contain additional contribution instructions specific to that project. When they do, those instructions supplement the organization-wide guidelines here.

A typical contribution looks like:

1. Find or open an issue describing the change.
2. Discuss larger changes before investing significant implementation effort.
3. Fork the repository and create a focused branch.
4. Implement the change with appropriate tests and documentation.
5. Open a pull request describing what changed and why.
6. Work with maintainers during review.

Small fixes don't need unnecessary ceremony. If you've found a typo, documentation issue, small bug, or similarly straightforward improvement, feel free to open a pull request.

## Discussions

GitHub Discussions in this repository are the primary place for conversations that span Exalynt as a whole.

Use Discussions for things like:

- Questions about Exalynt
- Ideas for new projects
- Software engineering discussions
- Feedback about the organization or ecosystem
- Requests for guidance
- Community announcements
- Topics that don't belong to a single repository

Project-specific bugs and actionable feature requests should generally be opened as issues in the relevant project repository.

## Our Engineering Philosophy

Exalynt exists to pursue excellence in software engineering—not perfection.

We value software that is:

- **Simple** — Complexity should earn its place.
- **Reliable** — Software should behave predictably and fail thoughtfully.
- **Maintainable** — Code is read and changed far more often than it is written.
- **Observable** — Production systems should tell us what they are doing.
- **Pragmatic** — Good engineering serves real problems rather than abstractions for their own sake.
- **Open** — Sharing knowledge makes the entire engineering community stronger.
- **Continuously improving** — Excellence is a direction, not a destination.

These principles guide Exalynt, but they aren't intended to impose one way of building software. Thoughtful disagreement and different engineering perspectives are welcome.

## Community Standards

Participation in Exalynt projects and community spaces is governed by our [Code of Conduct](CODE_OF_CONDUCT.md).

We want Exalynt to be a place where engineers can disagree, debate tradeoffs, ask questions, and challenge ideas while treating each other professionally and respectfully.

## Security

If a repository provides a security policy, follow the reporting instructions in that policy.
